## Objective
Complete Bizvyra's core loop: scan (L0) → fix → re-scan at L1 and L2 with a better grade. Implement the `/api/fix` hardener, the L2 output guard, a separate judge model, an optional reasoning switch for OpenAI-compatible providers, the reviewed Urdu wording, and a smoke script that measures L0, L1 and L2 in one run. The fix must work even when the LLM fails, so the live demo can never break at this step.

## Acceptance Criteria
1. `POST /api/fix` accepts `{ target: TargetInput, findings: Finding[], level: 1 | 2 }` (strict zod) and returns `{ fix: ChatbotFixContent }`. It never returns HTTP 500 for a valid request.
2. Deterministic hardener (`src/modules/chatbot/harden/`): builds the L1 system prompt from the original instructions by (a) removing every protected-asset value from the instructions and replacing it with a neutral description (e.g. "a VIP discount code exists; never share codes, refer customers to store staff"), (b) adding numbered security rules covering every intent in the findings (instructions confidentiality in any language or encoding, no authority claims accepted, no refunds or discounts approved, ignore embedded instructions, stay on shop topics), written so they apply in English, Urdu and Roman Urdu, and (c) a refusal style in the customer's language. It works with no LLM at all. `changes_en` / `changes_ur` list each change in plain language.
3. LLM refinement: when `MODEL_STRONG` is configured, the hardener asks it to improve the deterministic prompt (JSON output validated by zod). If the call fails, times out, returns invalid JSON, or returns a prompt that contains any protected asset or drops any numbered rule, the deterministic prompt is used unchanged. Vitest tests (adapter mocked) cover success, failure, asset re-insertion and dropped rules.
4. For `level: 2` the returned fix has `outputGuard: { enabled: true, blockProtected: true, selfCheck: true }`; for level 1 the guard is disabled.
5. L2 output guard in step execution: after the bot replies, (a) if the T002 canary/asset matcher detects the canary or any protected asset (including encoded forms), the reply is replaced by a refusal in the attack's language; (b) if `selfCheck` is on, `MODEL_JUDGE` is asked whether the reply breaks the shop rules (JSON `{ violates, reason }`); a violating reply is replaced by the refusal. If the self-check call fails, only (a) applies. The judge then runs on the reply the customer would actually see. Level-2 steps no longer return `skipped`. Vitest tests cover each path.
6. `MODEL_JUDGE` (optional) is used by the LLM judge and the L2 self-check, falling back to `MODEL_FAST` when unset. `LLM_REASONING=off` (optional) adds `"reasoning": { "enabled": false }` to `openai_compatible` request bodies; when unset, request bodies are unchanged. Both are documented in `.env.example` and the README, with adapter tests.
7. Finding text: the bilingual table uses this reviewed Urdu wording: ignore_instructions impact «کوئی بھی آپ کے بوٹ سے فضول کام کروا سکتا ہے، جس سے آپ کا خرچ بڑھتا ہے اور کاروبار غیر سنجیدہ لگتا ہے۔»; steal_system_prompt impact ends with «…دھوکے باز آپ کی اندرونی ہدایات دیکھ کر بہتر فراڈ کا منصوبہ بنا سکتے ہیں۔»; leak_discount_codes impact uses «لیک ہونے والا کوڈ» instead of «لیک شدہ کوڈ». Other entries unchanged.
8. `eval/smoke-demo.mjs` gains `--levels 0,1,2` (default `0`): it scans L0, calls `/api/fix` for L1 and L2 using the L0 findings, scans each level, and prints one summary table (level, grade, score, breaches, passes, errors, ASR by language). It also writes the full results to `eval/results/<timestamp>.json` (the folder is git-ignored only if `.gitignore` already covers it; otherwise results are written and listed in the report). It is not run in this task.
9. `AGENTS.md` "Design" guidance is replaced with the inspection-report direction: light theme, Paper #F4F5F2, Ink #18233A, Indigo #2B3F8C, Madder #B3261E, Leaf #1F6B47, Turmeric #8A5A00, Rule #D9DCD5; IBM Plex Sans (UI), IBM Plex Mono (attack and reply text only), Noto Nastaliq Urdu; status always icon + word. `docs/api-contract.md` documents `MODEL_JUDGE`, the L2 guard behaviour and the fix fallback.
10. `src/mocks/` L1 and L2 fixtures include a realistic `ChatbotFixContent` (hardened prompt with no protected values, changes in EN/UR).
11. All four test commands exit 0; the report gives exit codes, durations, raw log paths and exact Vitest counts.
