## Objective
A live scan on a free or low-tier LLM key must finish with real results, not a wall of errors. A real run with Gemini's free tier (`gemini-2.5-flash`) produced 25 errors out of 30 steps, all "The bot could not be reached" within ~200 ms: the provider rejected requests for exceeding its per-minute limit. Make the adapter retry rate-limited and temporarily unavailable calls with backoff, make scan concurrency configurable, and let `LLM_REASONING=off` also disable Gemini's thinking step for speed.

## Required Context

- `src/core/llm/adapter.ts` and its tests, the `/api/scans` route, `eval/smoke-demo.mjs`
- The newest file in `eval/results/` (the failing real run)

## Acceptance Criteria
1. The adapter retries a call when the provider answers HTTP 429, 500, 502, 503 or 504, or the network fails before a response: up to 3 retries with exponential backoff and jitter (about 1 s, 2 s, 4 s), honouring a `Retry-After` header (seconds or HTTP date) when present, capped at 10 s per wait. All attempts together stay within a total budget of 30 s, after which it returns `{ ok: false }` as today. It never retries HTTP 400, 401, 403 or 404. The error kind (`rate_limited`, `unavailable`, `timeout`, `auth`, `bad_request`, `other`) is part of the returned failure.
2. Error findings name the cause in plain language using that kind, e.g. "The AI provider is rate-limiting requests (too many per minute). Counted as an error, not as a pass." Keys and raw provider bodies never appear.
3. `SCAN_CONCURRENCY` (integer 1–5, default 3) sets the `concurrency` value returned by `POST /api/scans`. `eval/smoke-demo.mjs` already uses the returned value; confirm it does, and add `--concurrency N` to override it for local runs.
4. With `LLM_PROVIDER=gemini` and `LLM_REASONING=off`, request bodies include `generationConfig.thinkingConfig.thinkingBudget = 0`. When `LLM_REASONING` is unset, Gemini request bodies are unchanged. The `openai_compatible` behaviour from T003 is unchanged.
5. `.env.example`, the README (a short "Free-tier keys" note: set `SCAN_CONCURRENCY=1` and `LLM_REASONING=off`) and `docs/api-contract.md` document both settings and the retry behaviour.
6. Vitest tests (fetch mocked, timers faked) cover: 429 then success, 429 with `Retry-After`, 503 three times then failure, no retry on 401/404, total budget exceeded, the error kinds, the concurrency setting with invalid values falling back to 3, and the Gemini thinking-budget body.
7. All four test commands exit 0; the report gives exit codes, durations, raw log paths and exact Vitest counts.
