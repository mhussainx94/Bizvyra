## Summary

**Verify failure:** `harden.test.ts` › "removes prompt-mode values, including spaced, lower-case and Urdu-digit copies" timed out at 5000 ms (6099 ms in `.ai/verify/T004-1-1445/cmd-3.log`). It also took 3284 ms when it passed (`.ai/runs/T004-1-1445/e1-vitest-verbose.log`).

**Root cause, measured:** the cost was not mainly decoding. It was V8 compiling the spaced secret regexes from `secretPatterns()`.
- Each regex has a case-insensitive `[^\p{L}\p{N}]{0,3}` between every character, with flags `giu`.
- V8 takes about 0.4–0.8 s to compile one of these in `u` mode the first time it runs. A plain `new RegExp` cache does not help, because each value has a different source.
- The test's prompt has 3 values with 2 patterns each. The first runs were 831 ms for `SUPP-9921-LHR`, 788 ms for `0300-1234567` and 137 ms for `Qx7!pass`. A profile of `stripProtected` alone gave 1824.6 ms.
- `normalize`, `encodedChunks` and `views` together took under 1 ms on the same text.

**Fix:**

1. **`src/modules/chatbot/judge/redact.ts`, `secretPatterns()`:** the flags are now `giv` instead of `giu`. The sources are unchanged.
   - The `v` flag (Unicode sets) gives the same matches for these patterns, because `\p{L}`/`\p{N}` are closed under case folding and the classes hold only letters, digits and Eastern digits. V8 compiles them in a few ms.
   - Measured: 550 ms (`giu`) vs 4.3 ms (`giv`) for one pattern. 200 replaces on a 4.6 KB text took 446 ms vs 13 ms.
   - This also speeds up `redact()` in the judge path, which uses the same function.
2. **`src/modules/chatbot/harden/protect.ts`:** the work is restructured as requested.
   - A `Detector` is built once per value. It holds the compiled `secretPatterns`, the normalised needle and its reverse, and the whole-token patterns for short values.
   - The detectors are merged once for "any value". The patterns are no longer rebuilt per line or per call.
   - **Shared regexes:** they are global, so `testAny` resets `lastIndex` before `.test()`.
   - **Views:** `stripProtected` decodes the instructions once (`views(instructions)`) and reuses that for every per-value check. Before, `views` was rebuilt once per value.
   - **Prefilter:** before any base64/hex decoding, `normalize(text)` is checked for the needle or its reverse. A hit returns at once. A miss falls through to the full `matchAssets` decode. This only short-cuts to `true`, so it cannot miss anything.
   - The replacement order is the same as before: values longest first, each value's patterns in order.
3. **Pre-existing crash fixed (same line):** for values shorter than `MIN_ASSET_CHARS`, the escaping turned `-` into `\-` outside a character class. In `u` (and `v`) mode that is a SyntaxError ("Invalid escape"), so a short value such as `A-1` threw inside `stripProtected` / `redact`. `-` is no longer escaped there, because it is a literal outside a class. I added one regression test for this.

**Detection is not weakened:**
- All existing assertions are unchanged, and the full suite passes.
- E3 ran a fuzz test of 63 000 cases. It compares the new `giv` patterns with the old `giu` patterns (same source) using `String.replace`. The values were the 3 demo values plus 8 others: digits, Urdu, `ß`, `KELVIN` and a short value. The texts were random noise around copies with flipped case, separators, Eastern digits, reversal, `ſ`, `K` (Kelvin sign), `ẞ`, `İ`, NBSP, ZWSP and emoji. Result: **0 differences**.
