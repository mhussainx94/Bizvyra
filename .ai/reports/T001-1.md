### C10: SSRF guard

`src/core/security/ssrf.ts` `checkUrl()`:

- resolves DNS (`dns.promises.lookup`, `all: true`, injectable for tests) and rejects if **any** resolved address is blocked
- blocks:
  - IPv4: `0/8`, `10/8`, `100.64/10`, `127/8`, `169.254/16`, `172.16/12`, `192.168/16`, the test and benchmark nets, multicast and reserved
  - IPv6: `::`, `::1`, `fc00::/7`, `fe80::/10`, `fec0::/10`, multicast, documentation, Teredo
  - IPv4 embedded in IPv6 (mapped, translated, compatible, NAT64, 6to4)
- also rejects:
  - non-http(s) schemes
  - credentials in the URL
  - `localhost`/`.local`/`.internal` names
  - DNS failure

`ssrf.test.ts` (40 tests, DNS mocked) covers:

- each listed range: `127.0.0.0/8`, `10/8`, `172.16/12` (both ends), `192.168/16`, `169.254/16` (metadata), `100.64/10` (both ends), `::1`, `fc00::/7` (including `fd00:ec2::254`), `fe80::/10` (including a zone id)
- IPv4-mapped IPv6 in dotted and hex forms
- 5 non-http schemes (ftp, file, gopher, javascript, data)
- IP literals, including decimal- and hex-encoded loopback
- an allowed public IP, plus boundary public IPs
- redirect re-checking, the 3-redirect cap, and manual redirect mode in `safeFetch`

Not imported by any route: per F4, the build route list contains only the 8 API routes, none of which imports `ssrf`.
