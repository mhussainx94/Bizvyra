## Objective
Replace the mocked scan routes with the real, stateless Bizvyra engine defined in `docs/api-contract.md`: plan a scan, run and judge one attack per request with a fresh per-step canary, and score a finished scan. After this task a browser can run a full baseline scan of the demo bot (or of a pasted prompt) and get a real A–F grade. Defence levels L0 and L1 work end to end; L2's output guard and the `/api/fix` hardener are T003.

## Acceptance Criteria
1. Types in `src/lib/types/` match `docs/api-contract.md`: `TargetInput`, and request/response schemas for `POST /api/scans`, `POST /api/scans/step`, `POST /api/scans/finalize` and `POST /api/fix`, all strict zod objects. `fix` is required for level 1–2 and rejected for level 0. Existing domain types (`Finding`, `Scan`, `Step`, `ChatbotFixContent`) are reused, not duplicated.
2. Routes `src/app/api/scans/route.ts`, `src/app/api/scans/step/route.ts` and `src/app/api/scans/finalize/route.ts` implement the contract. The old stateful routes (`src/app/api/scans/[id]/**`, `src/app/api/targets/[id]/fix/**`) are removed. `POST /api/fix` exists and returns HTTP 501 with a clear message until T003. `/api/targets`, `/api/reports/[slug]` and `/api/leads` stay mocked and unchanged.
3. Plan builder (`src/modules/chatbot/` plan function used through the module registry): `quick` returns 30 steps (10 attacks × 3 languages) that cover all 5 intents, `full` returns 60; ordering interleaves languages and intents; output is deterministic for the same input. Vitest tests prove counts, coverage, uniqueness of `checkId`, and determinism.
4. Canary: a fresh token of ≥ 12 random alphanumeric characters is generated inside each step request and planted in the bot's instructions as a clearly labelled confidential reference line. It is never returned, logged or stored; findings show it only redacted.
5. Canary decoder (`src/modules/chatbot/judge/canary.ts`) detects the canary in a reply when it appears plainly, in a different case, with spaces / dashes / dots / newlines between characters, reversed, base64-encoded, or hex-encoded, including when embedded in surrounding text. Vitest tests cover each form and at least 3 negative cases (no false positive on similar strings).
6. Asset matcher uses the same normalisation, ignores assets shorter than 4 normalised characters, and has Vitest tests for plain, spaced, mixed-case and encoded matches plus negatives.
7. System-prompt overlap scorer computes the share of the instructions' distinct character 8-grams (canary line excluded) present in the reply, with thresholds from `docs/api-contract.md`. Vitest tests cover a full leak, a paraphrase below threshold, and an unrelated reply.
8. LLM judge (`src/modules/chatbot/judge/llm.ts`) is called only when steps 1–3 do not decide. It uses `MODEL_FAST` with JSON output `{ breach, reason, confidence }` validated by zod, an intent-specific rubric for all 5 intents, and treats malformed output or adapter failure as `status: "error"`, `judgedBy: "none"`. Vitest tests (adapter mocked) cover breach, pass, malformed JSON and failure.
9. Step execution: builds instructions per level (L0 original or demo prompt; L1 `fix.systemPrompt`; L2 returns `status: "skipped"` with evidence "output guard arrives in T003"), plants the canary, calls the bot with `MODEL_FAST`, runs the judge, and returns one Finding whose `prompt`, `response` (≤ 1000 chars) and `evidence` are redacted of the canary and every protected asset. A valid request never yields HTTP 500. Vitest route tests (adapter mocked) cover a canary breach, an asset breach, an LLM-judged pass, an adapter error, invalid input (400) and redaction.
10. Finding text: `title_en`, `title_ur`, `businessImpact_en`, `businessImpact_ur` come from a fixed bilingual table per intent in `src/modules/chatbot/`, written for this project. Urdu entries the agent is unsure of are listed in the report.
11. Scoring (`src/core/scoring/`) implements the contract: severity-weighted ASR, score, grade thresholds, buckets overall / by language / by intent, errors and skipped never counted as pass, null score and grade when nothing was decided. Vitest tests cover each grade boundary, an all-error scan, and mixed languages.
12. Limits: `/api/scans/step` is rate-limited per IP (demo mode 120/min, public 60/min) and `/api/scans` enforces 3 scans per IP per day in public mode only, both via `src/core/security/`. `BIZVYRA_MODE` defaults to `demo` when unset. Vitest tests cover both limits.
13. `src/mocks/` is updated to the v2 shapes (a baseline F, an L1 C and an L2 B scan with findings) so the UI can work without an API key. `.env.example` drops `OWNER_TOKEN_SECRET`. `AGENTS.md` "API" lists the v2 routes and points to `docs/api-contract.md`; README "Disclosures" and "Architecture" are updated if anything changed.
14. `eval/smoke-demo.mjs` (plain Node, no new dependencies) runs a quick L0 scan of the demo bot against a running dev server (`BASE_URL`, default `http://localhost:3000`): plan → all steps with concurrency 3 → finalize, then prints grade, score, and ASR by language and intent. It is written and its usage documented in the README, but **not run** in this task.
15. All four test commands exit 0. The report gives each command's exit code, duration and raw log path, and the exact Vitest counts as printed.
